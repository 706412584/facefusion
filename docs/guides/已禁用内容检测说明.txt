已禁用所有内容检测功能
========================

说明：本文档早期版本写错了文件路径，且实际上"出片前内容检测"当时并没有真正关掉，
导致任务在"正在分析 100%"后静默失败（错误码 3）。2026-10-05 已修正并补齐，见下。

修改的文件（实际生效的）：
--------------------------

1. facefusion/workflows/to_video.py
   - 函数 analyse_video() 直接 return 0
   - 不再 import / 调用 content_analyser，出片前不再做 NSFW 预检

2. facefusion/workflows/to_image.py
   - 函数 analyse_image() 直接 return 0
   - 同样不再做 NSFW 预检

3. facefusion/uis/components/preview.py
   - 预览界面的内容检测已注释
   - 预览时不再模糊处理画面

4. facefusion/streamer.py
   - 摄像头流媒体的内容检测已注释
   - 实时处理时不再中断

注意：早期文档写的 image_to_video.py / image_to_image.py 是**错误**的。
这两个文件只是任务编排（按顺序调用 to_video.py / to_image.py 里的函数），
真正做 NSFW 判定的是 to_video.py / to_image.py 中的 analyse_* 函数。

检测逻辑（上游行为，本地已绕过）：
----------------------------------
1. 每秒采样一帧，用 3 个 NSFW 模型判定
2. 2/3 模型认为是 NSFW 则标记该帧
3. 采样帧中 > 10% 被标记 → analyse_video 返回 True → 错误码 3，终止处理

影响：
------
- 所有视频和图片都可以正常处理
- 预览功能正常显示，不会被模糊
- 摄像头实时处理不会被中断
- 不再有 "rate > 10%" 的限制

⚠️ 合并上游时必须复查（上游会周期性恢复该检测）：
-------------------------------------------------
- facefusion/workflows/to_video.py 的 analyse_video() 应为 return 0
- facefusion/workflows/to_image.py 的 analyse_image() 应为 return 0
- 两处都不应再出现 `from facefusion import content_analyser` 或 analyse_* 调用

合并后快速检查：

本 fork **不修改** content_analyser.py，所以哈希校验依旧通过；
关检测只改 workflows/to_video.py 与 to_image.py 的调用点。
