Instant Runner 工作流程说明
==============================

问题：点击"开始"后，显示"正在分析 100%"就停止了

★ 更正（2026-10-05）：
  早期本文档把原因归为"任务队列卡住"，这是**误判**。
  真正原因是**出片前的 NSFW 内容检测**把任务判为不适当内容后返回错误码 3。
  判定方法：看"正在分析"那行的 rate，若明显 > 10（如 72.7）即是内容检测。
  详见 docs/guides/内容检测问题说明.txt 与 已禁用内容检测说明.txt。
  本 fork 已默认关闭该检测，正常不会再出现。

正确诊断顺序：
--------------
1. 看 .jobs/failed/ 里最新任务的步骤 status（应为 failed）
2. 看终端"正在分析"的 rate 是否 > 10 → 内容检测
3. 看是否报 flac/音频错误 → 见下方"flac 音频坑"
4. 以上都不是，再怀疑队列/GPU

flac 音频坑（2026-10-05 修复）：
-------------------------------
若界面音频编码器选的是 flac，输出 mp4 时 ffmpeg 会判为"实验特性"，
导致写头失败：输出 0 字节、headless-run 返回 1，但日志仍打印"成功"。
涉及三处 ffmpeg 调用，都必须带 -strict -2：
  - restore_audio
  - replace_audio
  - concat_video  ← job_runner.finalize_steps 会走到这里，最易遗漏
排查：ls -la 输出文件，若为 0 字节即命中。
临时规避：把音频编码器改成 aac。

方案：清理任务队列
------------------
1. 运行: scripts\清理任务队列.bat
2. 关闭 FaceFusion
3. 重新运行: 启动FaceFusion.bat
4. 重新提交任务

方案：切换到 Job Runner 模式
----------------------------
在界面上：
1. 找到"界面工作流程"下拉菜单
2. 从 "instant_runner" 切换到 "job_runner"
3. 这个模式可以看到任务队列
4. 可以手动管理任务

检查任务状态：
--------------
查看 .jobs 目录：
- .jobs/queued/    - 等待执行的任务
- .jobs/failed/    - 失败的任务
- .jobs/completed/ - 完成的任务

如果 queued 目录有文件，说明任务在等待
如果 failed 目录有文件，说明之前的任务失败了

正确的处理流程：
----------------
1. 上传源文件（人脸照片）
2. 上传目标文件（视频）
3. 选择人脸（reference 模式）
4. 勾选处理器（face_swapper）
5. 勾选 CUDA（如果有 GPU）
6. 点击"开始"
7. 等待处理完成

GPU 相关（若处理很慢）：
-----------------------
- 检查是否勾选 CUDA / 执行提供商
- 任务管理器看 GPU 使用率
- 详见 docs/gpu/ 下的说明
